ជំពូក ៤ ការវិភាគ ការគ្រោង និងការអនុវត្ត (Analysis, Planning and Implementation)

៤.១ ការវិភាគ និងការសិក្សាលើប្រព័ន្ធ (Study And Analysis the System) បន្ទាប់ពីក្រុមសិក្សាស្រាវជ្រាវបានចុះសិក្សាផ្ទាល់ និងទទួលយកព័ត៌មានពីក្រុមហ៊ុន Yeung Shi Group រួមជាមួយការសម្ភាសន៍ជាមួយម្ចាស់ក្រុមហ៊ុន បានឃើញថា ប្រព័ន្ធគ្រប់គ្រងបច្ចុប្បន្ននៅមានលក្ខណៈសាមញ្ញ និងបច្ចេកទេសមិនទាន់គ្រប់គ្រាន់។ ការលក់ ការគ្រប់គ្រងស្តុកទំនិញ (ដូចជា គ្រឿងម៉ាស៊ីន គ្រឿងផ្សំអាហារ និងផលិតផលនាំចេញ-នាំចូល) និងការកត់ត្រាអតិថិជន ត្រូវបានកត់ត្រាលើសៀវភៅ និង Microsoft Excel ដែលពិបាកផ្ទុកទិន្នន័យ អាចធ្វើឲ្យទិន្នន័យមិនមានសុវត្ថិភាព ហើយងាយនឹងបាត់បង់ទិន្នន័យរបស់អាជីវកម្ម។ រូបរាងនៃឯកសារមិនមានភាពទាក់ទាញនិងមិនងាយស្រួលប្រើប្រាស់ ចំណាយពេលយូរក្នុងការស្វែងរកទិន្នន័យដូចជាឈ្មោះអតិថិជន និងប្រវត្តិទិញ។ វាក៏មានការលំបាកក្នុងការថែទាំទិន្នន័យ ដែលធ្វើឲ្យការគ្រប់គ្រងអាជីវកម្មជួបប្រទះភាពយឺតយ៉ាវ និងមិនអាចឆ្លើយតបតម្រូវការទាន់ពេល។

៤.២ ការវិភាគលើប្រព័ន្ធបច្ចុប្បន្ន(ចាស់) (Analysis The Current System) ក្រុមហ៊ុន Yeung Shi Group ជាក្រុមហ៊ុននាំចេញ-នាំចូល និងចែកចាយទំនិញជាច្រើនប្រភេទដូចជា គ្រឿងម៉ាស៊ីន (ម៉ាស៊ីនចំណីអាហារ និងម៉ាស៊ីនកសិកម្ម) សម្ភារៈអាំងនិងក្លាសេ គ្រឿងផ្សំ គ្រឿងផ្សំរសជាតិអាហារនិងភេសជ្ជៈ និងសំបកវេចខ្ចប់ ដែលមានសកម្មភាពលក់ និងគ្រប់គ្រងស្តុកដោយពឹងផ្អែកលើការកត់ត្រាដោយបុគ្គលិកផ្ទាល់។

៤.២.១ ការសង្កេតលើប្រព័ន្ធបច្ចុប្បន្ន តាមការសង្កេតរបស់ក្រុមសិក្សាស្រាវជ្រាវបានដឹងថា រាល់សកម្មភាពគឺមានភាពយឺត និងលក្ខណៈសាមញ្ញ។

៤.៣ ការវិភាគលើប្រព័ន្ធនៃការសិក្សា(Proposed System) បន្ទាប់ពីបានការសិក្សា និងវិភាគលើប្រព័ន្ធបច្ចុប្បន្នក្រុមសិក្សាស្រាវជ្រាវយើងខ្ញុំបានបង្កើតនូវប្រព័ន្ធលក់ និងគ្រប់គ្រងស្តុកអនឡាញ (E-Commerce and Inventory System) មួយដែលអាចឆ្លើយតបទៅនឹងតម្រូវការរបស់ក្រុមហ៊ុន Yeung Shi Group បានយ៉ាងល្អ។

ប្រព័ន្ធនេះផ្ដល់នូវមុខងារសំខាន់ៗដូចខាងក្រោម៖ * ប្រព័ន្ធចាប់ផ្ដើមពីជំហាន ចូលប្រើប្រាស់ (Login) ដោយ អតិថិជន និង អ្នកគ្រប់គ្រង។ * អតិថិជនអាចស្វែងរក មើលព័ត៌មានទំនិញ (គ្រឿងម៉ាស៊ីន និងគ្រឿងផ្សំ) និងអាចបញ្ជាទិញទំនិញបានយ៉ាងងាយស្រួលពីចម្ងាយ។ * អតិថិជនអាចធ្វើការទូទាត់ប្រាក់យ៉ាងរហ័សតាមរយៈប្រព័ន្ធ Bakong Payment។ * អ្នកគ្រប់គ្រងអាចបញ្ចូលទិន្នន័យទំនិញថ្មី កែប្រែព័ត៌មាន និងតាមដានចំនួនស្តុកដែលនៅសល់ក្នុងឃ្លាំងបានយ៉ាងងាយស្រួល។ * ប្រព័ន្ធនឹងធ្វើការកាត់ស្តុកដោយស្វ័យប្រវត្តិរាល់ពេលមានការបញ្ជាទិញទំនិញជោគជ័យ ដែលជួយកាត់បន្ថយភាពខុសឆ្គងក្នុងការកត់ត្រាដោយដៃ។ * អ្នកគ្រប់គ្រងអាចតាមដានស្ថានភាពនៃការកម្មង់ និងអាចចេញវិក្កយបត្រឌីជីថល (Digital Invoice) ជូនអតិថិជនបានភ្លាមៗ។ * ប្រព័ន្ធអនុញ្ញាតឲ្យអ្នកគ្រប់គ្រងទាញយករបាយការណ៍លក់ និងរបាយការណ៍ស្តុក ដើម្បីងាយស្រួលក្នុងការសម្រេចចិត្តបញ្ជាទិញទំនិញចូលឃ្លាំងបន្ថែមឲ្យបានទាន់ពេលវេលា។

[សូមបញ្ចូលរូបភាព new_system_structure នៅទីនេះ] រូបភាព ៤.៣០ រចនាសម្ព័ន្ធនៃប្រព័ន្ធថ្មី

  • Administrator (អ្នកគ្រប់គ្រងប្រព័ន្ធមេ) ៖ មានតួនាទីកំណត់សិទ្ធិអ្នកប្រើប្រាស់ គ្រប់គ្រងប្រព័ន្ធទូទៅ មើលរបាយការណ៍ចំណូលប្រចាំខែ/ឆ្នាំ និងត្រួតពិនិត្យរាល់ទិន្នន័យទាំងអស់នៅក្នុងប្រព័ន្ធដើម្បីធានាដំណើរការអាជីវកម្ម។
  • Staff / Inventory Manager (បុគ្គលិកគ្រប់គ្រងស្តុក) ៖ សិទ្ធិចូលប្រើប្រាស់ផ្តោតទៅលើការបញ្ចូលទំនិញថ្មី កែប្រែព័ត៌មានទំនិញ ត្រួតពិនិត្យចំនួនស្តុក និងរៀបចំទំនិញចេញតាមការបញ្ជាទិញរបស់អតិថិជន។ ទោះជាយ៉ាងណា ពួកគេមិនអាចផ្លាស់ប្តូរសិទ្ធិអ្នកប្រើប្រាស់ផ្សេងទៀតបានឡើយ។
  • Customer (អតិថិជន) ៖ អាចចូលប្រើប្រាស់ប្រព័ន្ធដើម្បីស្វែងរកទំនិញ មើលកាតាឡុក បញ្ជាទិញទំនិញ និងទូទាត់ប្រាក់តាមរយៈ Bakong។ អតិថិជនអាចមើលបានតែព័ត៌មានប្រវត្តិទិញទំនិញ និងវិក្កយបត្រផ្ទាល់ខ្លួនរបស់ពួកគេប៉ុណ្ណោះ។

៤.៣.១ លំហូរនៃឯកសារ ឬព័ត៌មាន (Document/Information Flow) ដើម្បីបង្ហាញពីលំហូរព័ត៌មាននៅក្នុងប្រព័ន្ធលក់ និងគ្រប់គ្រងស្តុកថ្មីនេះ ក្រុមយើងខ្ញុំបានប្រើប្រាស់ដ្យាក្រាមបរិបទ (Context Diagram) និងដ្យាក្រាមកម្រិតសូន្យ (DFD Level 0)។ ដ្យាក្រាមទាំងនេះជួយបង្ហាញយ៉ាងច្បាស់ពីដំណើរការនៃការផ្ទេរព័ត៌មានរវាងអ្នកប្រើប្រាស់ (អតិថិជន និងអ្នកគ្រប់គ្រង) ទៅកាន់ប្រព័ន្ធ ព្រមទាំងបង្ហាញពីរបៀបដែលទិន្នន័យបញ្ជាទិញ និងទិន្នន័យស្តុកត្រូវបានរក្សាទុកយ៉ាងមានសុវត្ថិភាព។ ការបង្ហាញជាទម្រង់ដ្យាក្រាមនេះ ធ្វើឲ្យការត្រួតពិនិត្យ និងការអភិវឌ្ឍប្រព័ន្ធកាន់តែមានភាពងាយស្រួលនិងច្បាស់លាស់។

• ទំព័រគ្រប់គ្រងទំនាក់ទំនង (Contact Management) ៖ ជាទំព័រសម្រាប់អ្នកគ្រប់គ្រងពិនិត្យមើល និងឆ្លើយតបទៅនឹងសារសាកសួរព័ត៌មាន ឬបញ្ហាផ្សេងៗដែលអតិថិជនបានផ្ញើមកកាន់ក្រុមហ៊ុន។ [ដាក់រូបភាព ទំព័រគ្រប់គ្រងទំនាក់ទំនង នៅទីនេះ] រូបភាព ៤.៨០ ទំព័រគ្រប់គ្រងទំនាក់ទំនង

• ទំព័រគ្រប់គ្រងការបញ្ជាទិញ (Order Management) ៖ ជាកន្លែងសម្រាប់គ្រប់គ្រងរាល់ការបញ្ជាទិញរបស់អតិថិជន ពិនិត្យមើលការទូទាត់ប្រាក់ និងស្ថានភាពនៃការបញ្ជូនទំនិញ។ [ដាក់រូបភាព ទំព័រគ្រប់គ្រងការបញ្ជាទិញ នៅទីនេះ] រូបភាព ៤.៨១ ទំព័រគ្រប់គ្រងការបញ្ជាទិញ

• ទំព័រអ្នកប្រើប្រាស់ (Users Page) ៖ គឺជាកន្លែងសម្រាប់បង្កើតគណនីអ្នកប្រើប្រាស់ថ្មី (បុគ្គលិក) និងកំណត់តួនាទីសិទ្ធិប្រើប្រាស់ប្រព័ន្ធ។ [ដាក់រូបភាព ទំព័រអ្នកប្រើប្រាស់ នៅទីនេះ] រូបភាព ៤.៨២ ទំព័រអ្នកប្រើប្រាស់

• ទំព័រកំណត់ត្រាសកម្មភាព (Audit Log) ៖ ជាទំព័រសម្រាប់ត្រួតពិនិត្យ និងតាមដានរាល់សកម្មភាពរបស់អ្នកប្រើប្រាស់ (Admin & Staff) ដែលបានធ្វើប្រតិបត្តិការនៅក្នុងប្រព័ន្ធ។ [ដាក់រូបភាព ទំព័រកំណត់ត្រាសកម្មភាព នៅទីនេះ] រូបភាព ៤.៨៣ ទំព័រកំណត់ត្រាសកម្មភាព

• ទំព័រការកំណត់ (System Settings) ៖ ជាកន្លែងសម្រាប់រៀបចំ និងកែប្រែការកំណត់ទូទៅរបស់ប្រព័ន្ធទាំងមូល ដូចជាឈ្មោះគេហទំព័រ អ៊ីមែល លេខទូរស័ព្ទ និងអាសយដ្ឋាន។ [ដាក់រូបភាព ទំព័រការកំណត់ នៅទីនេះ] រូបភាព ៤.៨៤ ទំព័រការកំណត់

៤.៥.២ ការរចនា អន្តរមុខ (Interface) UI មានតួនាទីសំខាន់ក្នុងការធ្វើឲ្យប្រព័ន្ធមានភាពងាយស្រួលប្រើ។ ក្រុមបានប្រើ Figma ដើម្បីបង្កើត UI Mockups សម្រាប់ទំព័រដូចជា ទំព័រដើម ទំព័រលម្អិតគ្រឿងម៉ាស៊ីន ផ្ទាំងគ្រប់គ្រង និងប្រព័ន្ធបញ្ជាទិញ។ ការរចនាផ្អែកលើលក្ខណៈប្រើប្រាស់ងាយស្រួល ទំនើប និងផ្តល់បទពិសោធន៍ល្អដល់អតិថិជន។

៤.៥.៣ ការសរសេរកូដ បន្ទាប់ពីបានរចនារូបរាងថ្មី និងគ្រប់ផ្នែកនៃប្រព័ន្ធរួចមក ការសរសេរកូដគឺជាជំហានសំខាន់ក្នុងការអភិវឌ្ឍប្រព័ន្ធ។ ការសរសេរកូដបានធ្វើឡើងដោយប្រើប្រាស់ទាំង Front-end និង Back-end ដូចជា៖ • Front-end: ប្រើប្រាស់ Next.js, React, និង Tailwind CSS ដើម្បីបង្កើតចំណុចប្រទាក់អ្នកប្រើប្រាស់ (UI) ឱ្យដំណើរការលឿន និងទាក់ទាញ។ • Back-end: ប្រើប្រាស់ Node.js, Express.js, និង Prisma ORM ភ្ជាប់ទៅកាន់ PostgreSQL សម្រាប់ដំណើរការទិន្នន័យ រក្សាសុវត្ថិភាពខ្ពស់ និងធ្វើសម្របសម្រួលអំពី សំណើ/ការឆ្លើយតប API។ កូដត្រូវបានអភិវឌ្ឍន៍ទៅតាមគោលការណ៍ដែលមានរបៀបរៀបរយ ដើម្បីជួយឲ្យសមាសធាតុកម្មវិធីមានភាពងាយស្រួលក្នុងការថែទាំ។ ក្រុមការងារក៏បានប្រើកម្មវិធី VS Code សម្រាប់ការសរសេរកូដ និងប្រើ Git ដើម្បីគ្រប់គ្រងកំណែនៃប្រភពកូដ។

៤.៥.៤ សាកល្បង និង កែប្រែកំហុស មុនពេលដាក់ប្រព័ន្ធគ្រប់គ្រងការលក់នៃក្រុមហ៊ុនយ៉ាងស៊ឺគ្រុប ឲ្យប្រើប្រាស់ ក្រុមការងារត្រូវអនុវត្តការតេស្តសាកល្បងប្រព័ន្ធជាមុនសិន ដើម្បីស្វែងរកកំហុសដែលអាចកើតមាន។ យើងបានធ្វើតេស្តលើមុខងារបញ្ចូលផលិតផល ការបង្កើតការបញ្ជាទិញ និងការបញ្ជូនទម្រង់ស្នើសុំ (Inquiry)។ ការកែប្រែកំហុសប្រព័ន្ធ ជាដំណើរការកែសម្រួលកំហុសដែលបានរកឃើញក្នុងអំឡុងពេលសាកល្បង។ ដោយការជ្រើសយកវិធីសាស្រ្តនៃ SDLC (វដ្តជីវិតនៃការអភិវឌ្ឍន៍ប្រព័ន្ធ) ក្រុមសិក្សាស្រាវជ្រាវអាចដោះស្រាយកំហុសបានយ៉ាងមានប្រសិទ្ធភាព និងធានាថាប្រព័ន្ធមានសុវត្ថិភាពខ្ពស់ ដំណើរការរលូន។
